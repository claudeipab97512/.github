<p>问"家宽 IP 怎么选"，十个人里九个会给出同一个说法：看纯净度。这话没错，但对选型没有指导意义——纯净度测不出来，能测的是线路、延迟、在线率、可更换性。这篇把"家宽"拆成四层，每层给一个能自己量出来的指标，最后按层打分横向比较，而不是听卖家一句"原生家宽"就下单。</p>
<h2>一、把家宽拆成四层，别混着评</h2>
<p>同一条出口，在不同层上表现可能完全相反。线路归属写着某国电信，延迟却常年 300 毫秒；在线率 99%，但一天掉三次线，每次 IP 都变。混在一起评，最后只能凭感觉。拆成线路层、性能层、可用层、运维层，每层单独打分，问题才落得下去。</p>

<h2>二、线路层：ASN 和运营商名字要对得上</h2>
<h3>先看 ASN，再看名字</h3>
<p>很多人只看到 country 写着 US 就放心了，其实要看 asn 和 org。住宅宽带的 ASN 通常归属当地电信或有线电视运营商，org 里会出现 Comcast、Spectrum、AT&amp;T、Verizon、NTT、KDDI 这类名字；机房段的 org 则是 Amazon、Google Cloud、DigitalOcean、OVH 一类。名字对不上，后面几层再漂亮也是白搭。</p>
<h3>再看 /24 邻居密度</h3>
<p>一个 /24 段里如果只挂了几十个地址，邻居干扰小；如果挂着几百个地址、还混着大量短生命周期域名，说明这段被反复使用过。查法很简单，把目标 IP 拿去 ipwho.is 看 connections，再配合公开的段扫描结果对照，心里就有数了。</p>
<h2>三、性能层：延迟要分时段测，别只测一次</h2>
<p>下午三点测出来的 90 毫秒，和晚上十点测出来的 260 毫秒，是两条完全不同的线。家宽出口的瓶颈通常在晚高峰的上行带宽，跨境链路还要叠加国际出口拥塞。至少要取三个时段：当地 10:00、19:00、22:00，各测 100 个包。</p>

<h3>命令怎么写</h3>
<p>ping -c 100 目标域名 看基础 RTT；mtr -c 100 -r 目标域名 看逐跳丢包，重点看第 5 跳之后是否出现固定节点丢包；curl -o /dev/null -s -w "%{time_connect} %{time_total}\n" https://目标地址 连打 20 次，取中位数和 P95。三个数一起看，比单看平均值可靠。</p>
<h3>什么结果算能用</h3>
<p>P95 延迟 180 毫秒以内、抖动控制在 30 毫秒以内、丢包低于 1%，日常对话和页面操作基本无感。超过 300 毫秒会明显感到响应迟滞，长对话场景尤其明显。晚高峰相对白天的延迟抬升，控制在 30% 以内算正常区间。</p>

<h2>四、可用层：在线率和 IP 漂移要一起看</h2>
<h3>在线率怎么算才不作假</h3>
<p>服务商给的 99.9% 往往是"端口可连"，不代表出口可用。自己算：每 60 秒请求一次 https://ipinfo.io/ip，记录返回值和耗时，连续跑 7 天。成功率低于 99%、或单次连续失败超过 3 分钟，就算一次故障。这个脚本二十行就能写完，比任何 SLA 承诺都实在。</p>
<h3>IP 漂移是家宽的通病</h3>
<p>家庭宽带多为动态分配，掉线重播后公网 IP 会变。静态家宽（固定 IP）价格通常高一截，动态的要配好漂移后的处理流程：探活脚本发现 IP 变化就写日志并通知，账号侧是否需要同步调整，提前定好规则，别等出事再临时决定。</p>
<h2>五、运维层：更换机制和计费口径</h2>
<p>再好的线路也会坏，关键是坏了多久能换。采购前问清三件事：故障工单的响应时限、可更换次数是否受限、计费按 IP 条数还是按流量。按条数计费对长期挂机友好，按流量计费适合偶发大文件传输，混用场景要分开采购，别用一套账单套所有需求。</p>
<p>价格参考：动态家宽出口约 3–10 美元/条/月，固定 IP 家宽约 8–30 美元/条/月，带独享保证的更高，仅供参考。低于 2 美元还宣称独享家宽的，基本可以在心里打个问号。</p>
<h2>常见问答</h2>
<h3>家宽 IP 的延迟多少算正常？</h3>
<p>答：跨境访问下，P95 在 180 毫秒以内属于良好，180–300 毫秒可用但会有迟滞感，超过 300 毫秒建议换线。要按当地晚高峰时段测，不能只看白天的数值。</p>
<h3>在线率 99% 和 99.9% 差别大吗？</h3>
<p>答：按月度折算，99% 意味着每月可能有 7 小时不可用，99.9% 约 43 分钟。对需要长时间挂着的账号，这个差距会直接体现在运维工作量上。</p>
<h3>动态家宽的 IP 老变，会不会影响账号？</h3>
<p>答：会有影响，但不必然出问题。关键是变化频率和变化范围——同城同运营商内小幅变动通常影响较小，跨地区跳动就要留意，建议把漂移记录和账号异常记录放在一起对照。</p>
<h3>只测 ping 够不够判断一条线好不好？</h3>
<p>答：不够。ping 只看 ICMP，很多线路对 ICMP 做了限速。要叠加 mtr 看逐跳丢包、用 curl 看真实建连时间，再加长时间探活统计在线率，三个维度一起看。</p>
